# Roadmap

Implementation plan for Prism after the blueprint. Each ticket is self-contained for `/execute-ticket`: it names its inputs, its acceptance check and the ADR it serves. Tickets inside a phase may run in parallel unless a dependency is listed. The system version stays `0.1.0` until Phase 3 ships the vertical slice; `0.2.0` closes Phase 5.

### Wave 2 — the rest of the primitive layer, and Tooltip

A planning pass on 2026-09-24 audited the twelve specs left in the layer, and `Tooltip.yaml`. It read each against `spec/SCHEMA.md`, the ADRs, and what waves 1 and 1b recorded, at `bab02d8`. No stack implements any of the thirteen. So each spec is edited in place, and none moves its `specVersion` (SCHEMA's versioning rules).

**None of the thirteen can be built as written.** Most defects belong to one spec. Each row lists its own, and settles them before either stack is written, as P4-7 and P4-8 do. Other defects recur across the wave. The first component to settle one of those would write the rule for every spec after it, which is why wave 1b gave the chip and Backdrop tickets of their own. So three shared tickets come first:
- **P4-9**: the name of a control that draws no label.
- **P4-10**: the cells on `inverse`, `accent` and light glass, and which solid sits on the scheme's glass.
- **P4-11**: one haptic per action, P4-D3's renames, time in a snapshot, the row's geometry, hover timing and "required" said twice.

**Order.** P4-9 to P4-11 are spec, ADR and token work, and can run side by side. P4-10 reads the answers P4-7 and P4-8 record. After them come two tracks, which do not depend on each other.
- **Controls.**
  - Toggle, Checkbox and Radio first. They make up the settings row that ListRow and FormField, the next composites, compose. They are also the simplest anatomy to put P4-9 and P4-10 through.
  - Then TextField, TextArea, Select and SegmentedControl, the fields that FormField and SearchField compose. TextField settles P4-D13 and builds the rows the next two reuse. All three chip hosts wait for P4-8, which lands ADR-0037's enclosure.
  - Slider last, as the one gesture.
- **Readouts.**
  - Spinner first: Button already draws its arc privately on both stacks, which is P4-2's `DSGlyph` situation again.
  - Then ProgressBar, then ProgressRing, which reuses Spinner's arc, then Skeleton.
- **Tooltip** comes last. P4-D1 deferred it behind a trigger, and it attaches to IconButton, which is already implemented.

The two tracks meet only in the files every landing rewrites: the snapshot count, the gallery index, the parity report and both strings tables. So landings are serial even where the work runs in parallel.

**Sizes.** S is about a day, M two to three days, L four or more. Each is counted on both stacks, with the hand-back loop.

### Composites — the rest of the layer

A planning pass on 2026-09-25 read the twenty-four composite specs beyond Card, the ten data-viz specs and the three patterns at `202ea91`. It read each against `spec/SCHEMA.md`, the ADRs, what waves 1, 1b and 2 recorded, and the checks `202ea91` added. No stack implements any of them, so each is edited in place, and none moves its `specVersion` (SCHEMA's versioning rules).

**None of the composites can be built as written.** As in wave 2, most defects recur, and the first composite to meet one would write the rule for the rest. So five shared tickets come first:
- **P4-25**: slots that hold a component, and the examples that fill them.
- **P4-26**: names, words and one name per meaning.
- **P4-27**: the grounds a composite paints, and the grounds it sits on.
- **P4-28**: one presentation mechanism for the overlays, and one way to photograph it.
- **P4-29**: a second Apple snapshot target, without which no Tier 2 component has an Apple image.

**Order.** P4-25 to P4-28 are spec, SCHEMA and ADR work. They run side by side after P4-9 to P4-11, whose answers they extend to this layer. P4-29 is harness work and can start at once. Four tracks follow, each in the order of what its components compose:
- **Rows and status.** StatusPill and EmptyState first: they need only Backdrop (P4-6), and other composites hold them. Then ListRow, once Toggle (P4-12) and Avatar (P4-7) exist. Then Banner and Alert, whose content is rows, and Timeline.
- **Fields.** FormField once the controls it wraps exist (P4-12 to P4-19), then SearchField, then Stepper and Pagination.
- **Overlays.** Sheet first, because Popover and Menu fall back to it. Then Dialog, Popover and Menu, and Toast.
- **Navigation.** PillTabs, then TabBar and Toolbar and then TopBar, whose overflow goes into a Menu.

StatCard waits for DeltaBadge and Sparkline (P4-52, P4-53). The desktop composites come last: Sidebar, Table, ContextMenu and CommandPalette need P4-29, and Sidebar needs Tooltip (P4-24). P4-D1, P4-D5, P4-D7, P4-D10, P4-D11 and P4-D12 fire in this layer, and each row that fires one says so.
