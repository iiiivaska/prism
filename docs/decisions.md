# Prism — Decision Record

Canonical list of the founding decisions, taken with the owner on 2026-09-08 (#18 added 2026-09-14) in a one-question-at-a-time interview. #19–#25 were added on 2026-09-15 by the agents, under the owner's delegation, each on the evidence recorded in its ADR. #29 and #30 record the owner's review of the direction board on 2026-09-15: #29 the owner's decisions, #30 the semantic roles the board found. #31 records the owner's relicensing on 2026-09-22, which supersedes #28. Each decision has a matching ADR in `docs/adr/` with fuller context and citations; if the two disagree, the ADR wins. Nothing below is "TBD": every line was explicitly chosen.

|---|----------|--------------------|
| 1 | **Consumers are the owner's own apps; the primary developer is an AI agent.** Specs are machine-readable first; human docs are derived. Public release is not excluded. | All of the owner's projects are agent-driven (CLAUDE.md/AGENTS.md everywhere). An agent needs a strict contract, not a pretty site. |
| 2 | **Meta-system with a brand layer.** Three token tiers (primitive → semantic → component). A brand overrides primitives and a few semantic bindings. The default brand must be polished, not a grey skeleton. | The references are five different products with different accents; the owner's own products differ too. One-brand systems break at the first new product. |
| 3 | **Two implementations: SwiftUI and React.** One SPM package serves iOS, iPadOS, macOS, watchOS; one npm package (React + TypeScript + Tailwind v4 + CSS variables) serves web touch and desktop, including Electron. Minimum OS: iOS/iPadOS/macOS/watchOS **26**. | Native quality on Apple is non-negotiable for "very beautiful"; these are the two stacks every owner project already uses. SodaClone (macOS 15) upgrades later. |
| 4 | **Single DTCG 2025.10 JSON token source; everything else is generated by Style Dictionary 5 through a thin resolver driver** (Style Dictionary has no native resolver support yet; Terrazzo lints the resolver in CI). Outputs: Swift (typed `Color`/`Font`/`CGFloat`/`Spring` plus `.xcassets`), CSS variables + Tailwind `@theme inline`, TypeScript types, Tokens Studio and Figma-native flavors. CI fails if generated output is stale. Dimensions: brand × color scheme × density × input modality × motion × platform, expressed as DTCG resolver modifiers. | The previous system (RideVerse Glacier: Tokens Studio JSON + handwritten Swift + golden test) meant double edits and late drift. Generation removes the second edit. |
| 5 | **Figma is deferred; the system is "Figma-ready" from day one.** The living canon is a component gallery built from the web implementation plus SwiftUI snapshots. | 6 | **Component spec is a versioned contract; CI produces a cross-platform parity report; the whole system has ONE version.** Every change starts in the spec (bump the component's spec version); implementations declare which spec version they implement; the report goes red where an implementation lags. | This is the owner's explicit pain point ("change it once, see a warning everywhere else"). Discipline alone does not survive agent-driven development. |
| 7 | **Data-viz is a first-class module.** Apple: Swift Charts. Web: visx / d3-shape with our own SVG components. Wave 1: StatTile, Sparkline, RingGauge, Line/Area with target line. Wave 2: Bar, Legend, Tooltip, TimelineScrubber. Maps stay in apps; Prism only supplies map style tokens. | Charts carry half of the references' identity and are where agents produce the ugliest output without a spec. |

Role scale (display/title/headline/body/caption/metric), tabular figures for numbers (data and live values; static heroes proportional, ADR-0021), Dynamic Type and rem scaling are fixed by the system. | The references' identity lives in type; SF cannot be shipped to web; Cyrillic is required by the owner's localized apps. |
| 9 | **Materials in layers.** System chrome (nav bars, tab bars, toolbars, sheets) uses native Liquid Glass on Apple and a CSS imitation on web. Under Reduce Transparency, Increase Contrast and on watchOS, glass renders as the opaque `raised` surface, or `inverse` when selected (amended by ADR-0022). Four elevation levels. Web glass is accepted as visually different from Liquid Glass. | Keeps the native feel where Apple expects it and still allows the "glass card over a map" look; the rule is what separates the references from cheap glassmorphism. |
| 10 | **Three platform support tiers, plus density and input modality as token dimensions.** Tier 1 (iOS, iPadOS, web touch): full set. Tier 2 (macOS, web desktop): full set + desktop components (Sidebar, Table, ContextMenu, CommandPalette), hover, keyboard focus, compact density. Tier 3 (watchOS): deliberately small set from day one. Each spec carries `platforms: full / adapted / none`; `none` is a decision, not debt. Density: compact / regular / comfortable, plus `watch`, the watchOS default (amended by ADR-0029). Modality: pointer / touch (runtime, e.g. iPad + trackpad). | Five platforms are three input worlds; designing the watch in later would break the tokens. |
| 11 | **Accessibility in tiers, enforced in CI.** WCAG AA (4.5:1) for all functional text; tertiary/decorative text ≥ 24pt may go to 3:1; ultra-thin weights only for metrics ≥ 34pt and swapped to Regular under Increase Contrast / Bold Text (dark-scheme metrics only; Bold Text also steps every other weight on Apple, ADR-0021); glass becomes the opaque `raised` surface under Reduce Transparency or Increase Contrast (amended by ADR-0022); motion becomes crossfade under Reduce Motion (defined by #23); every spec has a mandatory accessibility block. A CI test checks every semantic text-on-surface pair per brand and scheme. | Preserves the references' character (big numerals, hero cards) without letting it leak into small text; turns "remember to" into "is checked". |
| 12 | **Five layers; v1 scope.** 0 Foundations, 1 Primitives, 2 Composites, 3 Data-viz, 4 Patterns. v1 = layers 0–2 complete, Data-viz wave 1, three patterns (dashboard grid, detail screen, adaptive shells). Out of scope on purpose: map, video player, rich-text editor, complex date pickers. | Prove the JSON→code→snapshot pipeline before going wide. |
| 13 | **Icons through a semantic registry.** Agents use `icon.search`, never raw names. The registry maps each name to an SF Symbol (Apple) and a Phosphor icon (web). CI validates the registry. | The only design where "change an icon" is a one-line edit; Phosphor's six weights match the references' thin line style. |

Git + GitHub from day one. | SPM requires the manifest at the repo root for URL dependencies; one tag = one system version for both stacks. |

| 19 | **Web runtime contract: six attributes named after the token-context fields. `data-ds-color-scheme` and `data-ds-density` work on any element; `data-ds-contrast`, `-transparency`, `-modality` and `-motion` work on `<html>` only. | 20 | **Brand model. A brand writes allowlisted `ref.*` ids only: neutral and accent ramps, eight `ref.color.slot.*` semantic slots that the scheme files alias, chart series, vivid gradients (nine, each declaring its temperature: amended by ADR-0029), font slots per platform, the type scale and radius steps. Status colors stay fixed. Every semantic color is an alias (tints add `app.prism.alpha`) or pure white or black; other `sys` values no brand owns may stay literal. Web: one `tokens.css` per brand, no `data-ds-brand`, one brand per document. Apple: `DSTokens` carries every repo brand; `DSTheme(brand:)` sets it once per scene, and colors come from `tokens.color` over one colorset namespace per brand. Brands live in Prism's `brands/`; a published CLI waits for a trigger. Native preset: system fonts on Apple, self-hosted Inter on web, no SF names in web output** (2026-09-15, amends 2, 3, 4, 7, 8 and 24) | A brand write to `sys.*` is always overwritten by `colorScheme`; literal tints kept the reference orange; SPM cannot swap `DSTokens`; Google Fonts breaks offline Electron launches and the GDPR. | 21 | **Typography rules.** Standard role weights are 300, 400 or 500. Thin weights (100–200) exist only as a metric role's dark-scheme `darkWeight`, at 34 px or more. Increase Contrast renders every weight below 400 at 400. Apple Bold Text renders `s ≤ 300 ? 400 : min(900, s + 200)`, which is SwiftUI's step for system text from 300 up; thin weights go to 400. One build rule derives both from the role data; there is no new resolver modifier. Static heroes use proportional figures; data and live values use tabular figures (`metric.md` is proportional, and the watch hero is a 40 px platform token: amended by ADR-0030). Font size is px in the source, rem on the web, and points scaled by `@ScaledMetric` along each role's `textStyle` on Apple. Tracking is em and line height a CSS-model ratio. Density does not change type, the brand type scale lies in [1, 1.25], and Prism has no italic. `fonts:check` counts a font as tabular when its digits have equal advances, with or without `tnum`. JetBrains Mono is pinned at the bundled 2.211. (2026-09-15, amends 4, 7, 8, 10 and 11) | One checkable rule replaces four conflicting ones. Every Apple route was measured on the iOS 26.5 and watchOS 26.5 simulators and on macOS 26.6. The decision keeps ADR-0011's "through the token layer" and decision #11's Regular fallback. |
| 22 | **Glass has one fallback: the opaque `raised` surface (raised painted over the page), or `inverse` for a selected glass surface. Surface alone picks it, reading Prism's context (`DSTokenContext` on Apple, `useTokenContext()` on the web), on watchOS, under Reduce Transparency, under Increase Contrast or over a backdrop that is not an image, a map or vivid. No token file writes a material fallback, and `sys.material.blur.enabled` is deleted. Glass recipes are typed tokens (`$root` fill, `blur` aliasing `ref.blur`, `saturate`, `edge.start`, `edge.end`, `grain`, `bloom`). Light glass has its own foreground (ink in light, white in dark). Glass follows the scheme: Surface `glass` renders light glass with ink tones in light and smoked glass in dark (amended by ADR-0029). Text on light glass, vivid and inverse is never dimmed with alpha. Dark glass sits only on backdrops where white holds 3:1. Every vivid gradient carries the full Card anatomy: every stop reaches 3:1 against white and the Card header block 4.5:1, checked by `tools/contrast`, with no text-safe zones. The default vivid is `gradient.vivid.default`: sky in light, plum-dusk in dark** (2026-09-15, amends 4, 9, 10 and 11) | One substitution rule replaces three conflicting answers and follows Apple's "backgrounds should be opaque". | 23 | **Motion tokens are Apple `(duration, bounce)` springs (duration 0.1–1 s, bounce 0–0.4) declared once on a literal `transition` token and inherited through `sys` and `comp` aliases; settle is the floor of the last millisecond the step response is ≥ 0.001 from its target (never `Spring.settlingDuration`); CSS `linear()` is sampled every millisecond from Motion's physics generator and simplified by Ramer–Douglas–Peucker (never `toString()` or `generateLinearEasing`); Reduce Motion is the `reduced` context layered over `default` (zero-bounce springs ≤ 0.30 s, durations ≤ 150 ms) plus one component rule: presentations crossfade at 150 ms, in-place scale and blur become opacity changes, in-place movement keeps its tightened spring, gestures track directly; components read Prism's context, never the OS; `interactive` keeps bounce 0; parity holds within 1e-4 physics, 1 ms settle and 0.0025 CSS curve.** (2026-09-15, amends 3 and 11) | Replaces three conflicting reduced-motion rules and the unusable Motion `toString()` plan with one definition; every number is reproduced on both stacks and checked in CI. |

## Deliberately deferred

- Figma plan and the moment Figma becomes a consumer (decision 5).
- The exact "Signature" typeface: chosen from rendered comparisons during research, then recorded in ADR-008.
- SodaClone stays on macOS 15 until it is upgraded; Prism does not ship a macOS 15 fallback.

## Process rules that follow from the decisions

1. A change to look or behavior begins in `spec/` (bump `specVersion`), then in `tokens/` if values move, then in each implementation. Never the other way round.
2. No raw hex, px or font names in implementation code. Only generated token accessors.
3. No icon without a registry entry. No color pair without passing the contrast test. No component without its accessibility block.
4. A platform marked `none` in a spec is not a TODO.
