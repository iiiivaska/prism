# Prism — Decision Record

Canonical list of the founding decisions, taken with the owner on 2026-09-08 (#18 added 2026-09-14) in a one-question-at-a-time interview. Each decision has a matching ADR in `docs/adr/` with fuller context and citations; if the two disagree, the ADR wins. Nothing below is "TBD": every line was explicitly chosen.

| # | Decision | One-line rationale |
|---|----------|--------------------|
| 1 | **Consumers are the owner's own apps; the primary developer is an AI agent.** Specs are machine-readable first; human docs are derived. Public release is not excluded. | All of the owner's projects are agent-driven (CLAUDE.md/AGENTS.md everywhere). An agent needs a strict contract, not a pretty site. |
| 2 | **Meta-system with a brand layer.** Three token tiers (primitive → semantic → component). A brand overrides primitives and a few semantic bindings. The default brand must be polished, not a grey skeleton. | The references are five different products with different accents; the owner's own products differ too. One-brand systems break at the first new product. |
| 3 | **Two implementations: SwiftUI and React.** One SPM package serves iOS, iPadOS, macOS, watchOS; one npm package (React + TypeScript + Tailwind v4 + CSS variables) serves web touch and desktop, including Electron. Minimum OS: iOS/iPadOS/macOS/watchOS **26**. | Native quality on Apple is non-negotiable for "very beautiful"; these are the two stacks every owner project already uses. SodaClone (macOS 15) upgrades later. |
| 4 | **Single DTCG 2025.10 JSON token source; everything else is generated by Style Dictionary 5 through a thin resolver driver** (Style Dictionary has no native resolver support yet; Terrazzo lints the resolver in CI). Outputs: Swift (typed `Color`/`Font`/`CGFloat`/`Spring` plus `.xcassets`), CSS variables + Tailwind `@theme inline`, TypeScript types, Tokens Studio and Figma-native flavors. CI fails if generated output is stale. Dimensions: brand × color scheme × density × input modality × motion × platform, expressed as DTCG resolver modifiers. | The previous system (RideVerse Glacier: Tokens Studio JSON + handwritten Swift + golden test) meant double edits and late drift. Generation removes the second edit. |
| 5 | **Figma is deferred; the system is "Figma-ready" from day one.** The living canon is a component gallery built from the web implementation plus SwiftUI snapshots. Tokens export to Tokens Studio; specs are structured so a Figma library can be built from them later. | The owner has no Figma-first process; a mirrored Figma library is the most expensive artifact and only pays off when someone designs in it. |
| 6 | **Component spec is a versioned contract; CI produces a cross-platform parity report; the whole system has ONE version.** Every change starts in the spec (bump the component's spec version); implementations declare which spec version they implement; the report goes red where an implementation lags. | This is the owner's explicit pain point ("change it once, see a warning everywhere else"). Discipline alone does not survive agent-driven development. |
| 7 | **Data-viz is a first-class module.** Apple: Swift Charts. Web: visx / d3-shape with our own SVG components. Wave 1: StatTile, Sparkline, RingGauge, Line/Area with target line. Wave 2: Bar, Legend, Tooltip, TimelineScrubber. Maps stay in apps; Prism only supplies map style tokens. | Charts carry half of the references' identity and are where agents produce the ugliest output without a spec. |
| 8 | **Typography: three brand-level font slots (`ui`, `display`, `mono`) with two presets.** "Native": SF Pro on Apple, Inter on web. "Signature": one open-license family bundled on every platform, chosen by rendered comparison. **Cyrillic is mandatory** (excludes Outfit, Urbanist and similar Latin-only faces). Role scale (display/title/headline/body/caption/metric), tabular figures for numbers, Dynamic Type and rem scaling are fixed by the system. | The references' identity lives in type; SF cannot be shipped to web; Cyrillic is required by the owner's localized apps. |
| 9 | **Materials in layers.** System chrome (nav bars, tab bars, toolbars, sheets) uses native Liquid Glass on Apple and a CSS imitation on web. Content uses three surfaces: `solid`, `vivid` (tokenized brand gradient), `glass`. Rule: glass only over imagery, maps or vivid surfaces; never glass-on-glass; no blur on watchOS. Four elevation levels. Web glass is accepted as visually different from Liquid Glass. | Keeps the native feel where Apple expects it and still allows the "glass card over a map" look; the rule is what separates the references from cheap glassmorphism. |
| 10 | **Three platform support tiers, plus density and input modality as token dimensions.** Tier 1 (iOS, iPadOS, web touch): full set. Tier 2 (macOS, web desktop): full set + desktop components (Sidebar, Table, ContextMenu, CommandPalette), hover, keyboard focus, compact density. Tier 3 (watchOS): deliberately small set from day one. Each spec carries `platforms: full / adapted / none`; `none` is a decision, not debt. Density: compact / regular / comfortable. Modality: pointer / touch (runtime, e.g. iPad + trackpad). | Five platforms are three input worlds; designing the watch in later would break the tokens. |
| 11 | **Accessibility in tiers, enforced in CI.** WCAG AA (4.5:1) for all functional text; tertiary/decorative text ≥ 24pt may go to 3:1; ultra-thin weights only for metrics ≥ 34pt and swapped to Regular under Increase Contrast / Bold Text; glass becomes `solid` under Reduce Transparency; motion becomes crossfade under Reduce Motion; every spec has a mandatory accessibility block. A CI test checks every semantic text-on-surface pair per brand and scheme. | Preserves the references' character (big numerals, hero cards) without letting it leak into small text; turns "remember to" into "is checked". |
| 12 | **Five layers; v1 scope.** 0 Foundations, 1 Primitives, 2 Composites, 3 Data-viz, 4 Patterns. v1 = layers 0–2 complete, Data-viz wave 1, three patterns (dashboard grid, detail screen, adaptive shells). First implementation step is a vertical slice: tokens → Surface, Text, Button, Card on both stacks with snapshots, to prove the pipeline. Out of scope on purpose: map, video player, rich-text editor, complex date pickers. | Prove the JSON→code→snapshot pipeline before going wide. |
| 13 | **Icons through a semantic registry.** Agents use `icon.search`, never raw names. The registry maps each name to an SF Symbol (Apple) and a Phosphor icon (web). Stroke weight is a token mapped to SF weights and Phosphor weights. System chrome on Apple always uses SF Symbols; product icons use one open set bundled everywhere. CI validates the registry. | The only design where "change an icon" is a one-line edit; Phosphor's six weights match the references' thin line style. |
| 14 | **Monorepo with `Package.swift` at the repository root.** Layout: `tokens/`, `brands/`, `spec/`, `swift/`, `web/`, `tools/`, `gallery/`, `docs/`, `agent/`. Distribution: SPM by git tag; npm via GitHub Packages under `@iiiivaska`. The `agent/` folder ships a Claude Code skill for consuming apps. Git + GitHub from day one. | SPM requires the manifest at the repo root for URL dependencies; one tag = one system version for both stacks. |
| 15 | **References are inspiration only.** Principles (hierarchy, surface logic, spacing rhythm, chart styling) are extracted; nothing is copied; no attempt to obtain the studio's sources; fonts and icons are open-license. Figma Community kits under permissive licenses may serve as *structural* checklists (states, variants), never as visuals. | Dribbble shots are RonDesignLab's portfolio; copying is both infringement and pointless for a meta-system. |
| 16 | **Name: Prism. Code prefix: `ds`.** Swift types `DS…`, CSS variables `--ds-…`, npm scope `@iiiivaska/prism-*`, GitHub `iiiivaska/prism` (ADR-0018; originally `iiiivaska/DesignSystem`, taken). | "Prism" says one system → many brands and nods to glass; `ds` avoids `PR` reading as pull request. |
| 17 | **First deliverable is a blueprint, not code.** Research → visual DNA → decision record and ADRs → token schema with the default brand → component specs for v1 → icon registry → repo skeleton with build/CI configs → agent skill → HTML direction board for visual sign-off → roadmap as tickets. Repository language: **English**; conversation with the owner: Russian. | Beauty cannot be judged from JSON; one HTML board is cheaper to redo than two implementations. |
| 18 | **Repository `iiiivaska/prism`, public** (taken 2026-09-14, amends 14 and 16). The name `DesignSystem` belongs to an earlier unrelated project; public visibility gives unmetered macOS CI. The ADR-0015 firewall and legal checkpoint still apply. | Keeps the earlier project intact; the `apple` CI job is not budget-limited. |

## Deliberately deferred

- Figma plan and the moment Figma becomes a consumer (decision 5).
- The exact "Signature" typeface: chosen from rendered comparisons during research, then recorded in ADR-008.
- SodaClone stays on macOS 15 until it is upgraded; Prism does not ship a macOS 15 fallback.

## Process rules that follow from the decisions

1. A change to look or behavior begins in `spec/` (bump `specVersion`), then in `tokens/` if values move, then in each implementation. Never the other way round.
2. No raw hex, px or font names in implementation code. Only generated token accessors.
3. No icon without a registry entry. No color pair without passing the contrast test. No component without its accessibility block.
4. A platform marked `none` in a spec is not a TODO.
